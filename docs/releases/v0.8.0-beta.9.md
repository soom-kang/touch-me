The [43-input manifest](v0.8.0-beta.9-inputs.json) matches the exact released tag.
The 42 build/package inputs stayed unchanged; final Cask metadata is the separate
publication input. At the native checkpoint the candidate had not been launched
and the old installed app/local archive/images were preserved. The outer DMG was
not code signed; checks cover image integrity/checksum and the signed inner app.
The later upgrade deliberately installed the verified public candidate.

The first style attempt exited 2 for missing locked `spoom 1.8.10`. Existing
compatible `1.8.9` through a process-only load path passed the same Cask rules.
No gem installation, configuration/trust write or additional Cask-rule exclusion
was used. Eight earlier releases, 16 asset metadata records and 16 tag refs
retained their identities; older asset bytes were not redownloaded.

### State preservation and remaining acceptance

The immediate App Management preflight passed in the actual `brew` host and
the normal upgrade preserved the outer directory. Postlaunch preferences,
saved-payload, guard and full recovery-manifest hashes match the preinstall
baseline: `resumeMapping=false`, active record 0, valid historical guard 1 and
archives 5. The earlier-boot guard and its matching archive are retained;
current-boot equality is not required by the no-active-record path.

The automation channel closed before a GUI permission reading, including
reset/retries. Initially the user reported one or more required permissions;
individual before flags are unknown. After approval/restart, the user confirmed
both Allowed in beta.9/build 27 at PID `35272`, with the exact public path/hash.
Normal Quit and native PID absence passed. This allowed A9 baseline is
**PASS_USER_REPORTED**; public beta.9 → beta.10 retention remains untested.

This experimental personal beta Tap has no Developer ID or notarization.
Fresh Gatekeeper, physical-device acceptance, public A → B retention and a
receiving Mac without installed signing identity or added trust remain
**NOT_RUN**. Preserve receipts, preferences, recovery, trust/developer settings
and prior publications. Do not reset recovery or permissions to produce a PASS.
See [Workflow](../../Workflow.md#public-signing-validation--2026-10-13) and
[Homebrew](../Homebrew.md).

### 변경

- Beta.9는 장기 `Touch Me Release Signing` 인증서로 서명했습니다. 빌드
  기본값은 ad hoc이며 인증서 서명에는 identity·인증서 pin을 명시해야 합니다.
  검사에 실패하면 ad hoc으로 전환하지 않고 중단합니다.
- 최초 ad hoc → 인증서 승인 뒤 사용자가 GUI beta.9/build 27의 두 권한 모두
  Allowed임을 확인했습니다. 개별 before 값은 미확인입니다. 정상 Quit과
  native PID 부재도 확인했으며 Start는 실행하지 않았습니다.
- 같은 인증서의 공개 beta.9 A → beta.10 B가 승인한 경로입니다. 두 공개 버전
  사이 권한 유지는 **NOT_RUN**입니다.

### 산출물·공개·upgrade

위 표에 실제 source/tag, 인증서·DR, 실행 파일·DMG, 공개·로컬 Tap 식별을
기록했습니다. 입력 43개는 정확한 release tag와 일치하고 익명 public DMG·
sidecar의 bytes·크기·hash·checksum 텍스트도 native 후보와 같습니다.
[Input manifest](v0.8.0-beta.9-inputs.json)의 빌드·패키징 입력 42개는 유지됐고
최종 Cask metadata를 별도 공개 입력으로 포함합니다.

2026-10-13 23:46:41 KST의 native checkpoint에서는 빌드·패키징 각 한 번을
exit 0으로 마쳤고 앱·DMG 검사와 정상 detach를 확인했습니다. 당시 후보는
실행하지 않았으며 기존 설치 앱·로컬 archive·이전 이미지를 보존했습니다.
바깥 DMG는 code signing하지 않았고 이미지 무결성·checksum과 내부 앱 서명을
확인했습니다. 이후 공개 후보로 정상 upgrade했습니다.

Upgrade 한 번을 2026-10-14 00:30:45 KST(2026-10-13 15:30:45 UTC)에 exit 0으로
마쳤습니다. 설치 파일 5개는 공개 후보와 같고 strict 인증서·DR을 확인했습니다.
바깥 디렉터리의 device·inode와 선택 Cask trust true·전체 Tap trust false도
유지됐습니다. Ruby 문법과 동등한 Homebrew Cask style 규칙은 통과했습니다.
첫 style 실행은 lock의 `spoom 1.8.10`이 없어 exit 2로 중단됐고 설치된 호환
버전 `1.8.9`를 해당 process의 load path로 사용했습니다. Gem 설치, 설정·trust
변경과 추가 Cask 규칙 제외는 없었습니다. 정확한 locked toolchain의 PASS는
아니며 online audit는 기존 합의에 따라 **BLOCKED**입니다. 이전 release 8개,
asset metadata 16개와 tag ref 16개는 식별을 유지했으며 과거 asset bytes를
다시 다운로드한 결과는 아닙니다.

### 상태 보존과 남은 acceptance

Upgrade 직전 실제 `brew` host의 App Management 조건을 확인했고 정상 교체에서
바깥 디렉터리를 보존했습니다. 실행 후 환경설정·저장 매핑·guard·전체 복구
manifest hash는 설치 전과 같습니다. `resumeMapping=false`, active record 0개,
유효한 기존 guard 1개와 archive 5개를 유지했습니다. 이전 boot의 guard와 일치하는
archive를 보존하며 active record가 없는 경로는 현재 boot와의 일치를 요구하지
않습니다.

자동 GUI channel은 reset·재시도 뒤에도 사용할 수 없었습니다. 최초에는
권한 하나 이상이 필요하다는 사용자 보고였으며 개별 before 값은 미확인입니다.
승인·재실행 뒤 정확한 공개 경로·hash의 PID `35272`에서 GUI beta.9/build 27의
두 권한 모두 Allowed임을 사용자가 확인했습니다. 정상 Quit과 native 부재도
확인했습니다. A9 허용 baseline은 **PASS_USER_REPORTED**이며 공개
beta.9 → beta.10 권한 유지는 아직 검증하지 않았습니다.

Developer ID와 공증이 없는 개인 beta Tap의 시험입니다. Fresh Gatekeeper,
실기기 acceptance, 공개 A → B 권한 유지와 서명 identity 설치·추가 trust가 없는
수신 Mac은 **NOT_RUN**입니다. Receipt, 환경설정, 복구, trust·developer 설정과
이전 산출물을 보존하며 PASS를 만들려고 권한이나 복구 기록을 초기화하지
않습니다. [Workflow](../../Workflow.ko.md#공개-서명-검증--2026-10-13)과
[Homebrew](../Homebrew.ko.md)를 참고하세요.
