# Touch Me v0.8.0-beta.3

## English

This beta restores touch mapping after screen lock and unlock without restarting the app, and reduces the device-discovery work that delayed recovery.

- Mapping intent survives a confirmed lock, sleep or inactive-session interruption. Resume requires the saved panel, USB location, display configuration and both permissions to match.
- Persistent display identity and a bounded recovery window handle temporary display changes around unlock. Explicit Stop, unrelated target changes and terminal errors still cancel automatic resume.
- HID discovery reuses descriptor data and skips detailed reads for unrelated USB interfaces while retaining all touchscreen candidates and their sibling safety checks. Incomplete descriptors block mapping.
- Callback cleanup uses the original registration context, and callbacks from devices outside the active mapping session are ignored.

The readiness retry window is ten seconds. It does not interrupt a native device call already in progress. Device-mode restoration errors remain visible and require **Retry restore** before mapping can restart.

Support remains one ZEUSLAP P16KT (`0x0457:0x0819`) on Apple Silicon with macOS 26 (Tahoe) or later, using an eligible external display. The app uses ad hoc signing without Developer ID signing or Apple notarization. Updates may require renewed Input Monitoring and Accessibility approval.

Download `touch-me-0.8.0-beta.3-arm64.dmg` and its `.sha256` file together, then verify before installing:

```bash
shasum -a 256 -c touch-me-0.8.0-beta.3-arm64.dmg.sha256
```

Install through the existing personal Homebrew Tap:

```bash
brew install --cask soom-kang/touch-me/touch-me
```

Before an upgrade or removal, select **Stop mapping**, confirm device-mode restoration, then quit normally. If restoration fails, stop the operation and retry recovery with the panel on the same USB port. See the [Homebrew guide](https://github.com/soom-kang/touch-me/blob/v0.8.0-beta.3/docs/Homebrew.md) for installation conflicts and update steps.

### Verification and limits

On 2026-10-08 (`Asia/Seoul`), the user confirmed that touch worked immediately after login following a lock/unlock cycle in build 18, which contains the recovery code included in this release. This is `PASS_USER_REPORTED` for one cycle; it does not establish an exact recovery duration or every interruption scenario. Earlier measured build 17 logs identified device discovery as the dominant delay. See the [lifecycle record](https://github.com/soom-kang/touch-me/blob/v0.8.0-beta.3/docs/qa/lifecycle-policy.md).

One release build and one packaging run produced build 19 with `TouchMeReleaseVersion=0.8.0-beta.3`. Compilation with warnings as errors, strict ad hoc signature verification, bundle metadata, exact license/icon content, arm64 packaging, DMG integrity and SHA-256 verification passed. All 23 source and packaging inputs match the release checkout. Command Line Tools emitted the existing non-fatal linker search-path warnings. The frozen DMG SHA-256 is `7f3b500c8efa0d7195e54f581fd0cc4d0fb6265ff54464b39ce6eeb9e7dfef76`. Public download and Homebrew audit results are recorded separately on the [published release](https://github.com/soom-kang/touch-me/releases/tag/v0.8.0-beta.3).

Cask Ruby syntax and Homebrew 7.0.8 style passed on the actual `Casks/touch-me.rb` file, with one file inspected and no offenses.

No new tests, dependencies or CI infrastructure were added. Existing packaging and core logic tests were not rerun for the version/documentation update. No GitHub Actions workflow is configured. The newly packaged release app has not been installed or run on the panel. Homebrew installation, Gatekeeper, sleep/wake and full logout/login checks are `NOT_RUN`. Abnormal-exit restoration remains unimplemented; reopening the app does not prove restoration of the pre-crash device mode.

## 한국어

화면 잠금·해제 후 앱을 재시작하지 않아도 터치 매핑이 자동으로 돌아오도록 수정했습니다. 복구를 지연시키던 장치 조회 작업도 줄였습니다.

- 잠금, 절전이나 사용자 세션 비활성화를 확인하면 재개할 의도를 보존합니다. 저장한 패널·USB 위치·화면 구성과 두 권한이 일치해야 재개합니다.
- 화면의 영구 식별자와 제한된 복구 구간으로 로그인 전후의 일시적인 화면 변경을 처리합니다. 직접 중지, 별도 대상 변경과 복구할 수 없는 오류는 자동 재개를 취소합니다.
- HID descriptor를 반복해서 읽지 않고 관련 없는 USB 인터페이스의 상세 조회를 줄입니다. 모든 터치 후보와 같은 장치의 형제 인터페이스는 계속 검사하며, descriptor가 불완전하면 매핑을 차단합니다.
- Callback을 등록했던 context로 정리하고 현재 매핑 세션에 속하지 않는 장치의 callback은 무시합니다.

준비 확인은 10초의 재시도 구간 안에서 진행합니다. 이미 실행 중인 장치 호출을 강제로 중단하는 timeout은 아닙니다. 장치 모드 복구 오류는 화면에 남으며 **복구 재시도**를 마쳐야 매핑을 다시 시작할 수 있습니다.

지원 범위는 Apple Silicon과 macOS 26(Tahoe) 이상에서 사용하는 ZEUSLAP P16KT(`0x0457:0x0819`) 한 대와 조건에 맞는 외부 화면입니다. Developer ID 서명과 Apple 공증 없이 ad hoc 서명을 사용합니다. 업데이트 후 입력 모니터링·손쉬운 사용 재승인이 필요할 수 있습니다.

DMG와 `.sha256` 파일을 함께 받아 위의 checksum 명령으로 확인한 뒤 설치하세요. Homebrew 설치 명령도 위와 같습니다. 업데이트·제거 전에는 **매핑 중지 → 장치 모드 복구 확인 → 정상 종료** 순서를 따릅니다. 복구가 실패하면 작업을 중단하고 같은 USB 포트에 패널을 연결해 복구를 재시도하세요. 설치 충돌과 업데이트 절차는 [Homebrew 안내](https://github.com/soom-kang/touch-me/blob/v0.8.0-beta.3/docs/Homebrew.ko.md)를 확인하세요.

### 검증 결과와 한계

2026-10-08(`Asia/Seoul`)에 사용자는 build 18의 잠금·해제 후 로그인하자마자 터치가 정상 작동했다고 확인했습니다. 해당 build에는 이번 release의 복구 코드가 들어 있습니다. 한 번의 `PASS_USER_REPORTED` 결과이며 정확한 복구 시간이나 모든 중단 상황을 보장하지 않습니다. 앞서 측정한 build 17 로그에서는 장치 조회가 지연의 대부분을 차지했습니다. 자세한 근거는 [lifecycle 기록](https://github.com/soom-kang/touch-me/blob/v0.8.0-beta.3/docs/qa/lifecycle-policy.md)에 있습니다.

Release 빌드와 패키징을 각각 한 번 실행해 `TouchMeReleaseVersion=0.8.0-beta.3`인 build 19를 생성했습니다. Warnings-as-errors 컴파일, strict ad hoc 서명, bundle metadata, 정확한 라이선스·아이콘 내용, arm64 패키징, DMG 무결성과 SHA-256 검사를 통과했습니다. 소스·패키징 입력 23개가 release checkout과 일치합니다. 기존 Command Line Tools의 linker search-path 경고는 빌드를 중단하지 않았습니다. 확정한 DMG SHA-256은 `7f3b500c8efa0d7195e54f581fd0cc4d0fb6265ff54464b39ce6eeb9e7dfef76`입니다. 공개 다운로드와 Homebrew audit 결과는 [공개 release](https://github.com/soom-kang/touch-me/releases/tag/v0.8.0-beta.3)에 별도로 기록합니다.

Cask Ruby syntax와 실제 `Casks/touch-me.rb`의 Homebrew 7.0.8 style 검사를 통과했습니다. 한 파일을 검사해 오류가 없었습니다.

새 테스트·dependency·CI 인프라는 추가하지 않았습니다. 버전·문서 갱신에서 기존 packaging·core logic tests는 재실행하지 않았으며 GitHub Actions workflow도 설정되어 있지 않습니다. 새로 패키징한 release 앱을 설치하거나 패널에서 실행하지 않았습니다. Homebrew 설치, Gatekeeper, 절전·복귀와 실제 로그아웃·로그인 검사는 `NOT_RUN`입니다. 비정상 종료 후 장치 모드 복구는 구현되지 않았으며 앱 재실행만으로 충돌 전 모드 복구를 확인할 수 없습니다.
