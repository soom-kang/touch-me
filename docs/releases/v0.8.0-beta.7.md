This prerelease includes safe USB-C reconnection handling from source baseline

### Changes

During the same app run, reconnecting one supported P16KT at the saved USB
location and display can resume mapping after fresh device, permission and
session checks. Readiness retries use the existing one-second timer and end ten
seconds after first device reappearance; repeated notifications do not extend
that deadline. Stop, target changes and normal Quit cancel the wait.

Only a freshly read `(0,0)` after exclusive open permits automatic Start.
A connection already in `(2,0)` requires informed manual Start and keeps that
mode after Stop. The app never writes an old connection's mode onto a new one.

When both exact recorded HID/USB services are proven ended on the same boot,
with authorized ownership and the exclusive lease, the app can archive the old
record as `disconnected-<nonce>.json`. This preserves an unconfirmed restoration.
A durable `reconnect-required.json` maintains fresh-mode checks after relaunch;
an unfinished cable-wait intent is not persisted. Uncertain identity, ownership,
lookup or storage blocks mapping. Active journal and saved-mapping formats are
unchanged. The DMG and Homebrew guidance now describe this policy.

### 변경

같은 앱 실행 중 지원 P16KT 한 대를 저장한 USB 위치와 화면에 다시 연결하면
장치, 권한과 세션 상태를 새로 확인한 뒤 매핑을 재개할 수 있습니다.
기존 1초 timer로 준비를 재시도하며 장치가 처음 돌아온 뒤 10초가 지나면
종료합니다. 반복 알림은 시간을 늘리지 않습니다. 중지, 대상 변경과 정상
종료는 대기를 취소합니다.

독점 open 뒤 새로 읽은 모드가 `(0,0)`일 때만 자동 시작합니다.
`(2,0)`이면 안내를 확인하고 직접 시작해야 하며 중지 후에도 현재 모드를
유지합니다. 옛 연결의 모드 값을 새 연결에 쓰지 않습니다.

같은 부팅에서 기록된 정확한 HID/USB 서비스가 모두 종료되고 소유권과
독점 lease가 확인되면 옛 기록을 `disconnected-<nonce>.json`으로 보존할
수 있습니다. 원복을 확인했다는 뜻은 아닙니다. 영구 저장한
`reconnect-required.json`은 재실행 후에도 새 모드 확인을 요구하며,
끝나지 않은 케이블 대기 의도는 저장하지 않습니다. 식별, 소유권, 조회나
저장이 불확실하면 매핑을 차단합니다. 기존 active journal과 저장한 매핑
형식은 유지합니다. DMG와 Homebrew 안내도 이 동작에 맞게 수정했습니다.
