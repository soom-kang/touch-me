### Changes

  requires confirmation before mapping starts.
- Start explains the current permission, device, display or session blocker in
  English and Korean; past failures are shown separately. Login-item launches
  remain in the menu bar.
- Queued HID reports preserve their callback coordinates. Incomplete or ambiguous
  contact descriptors block mapping.
- A separate recovery journal preserves the original device mode across process
  exit and completes verified predecessor recovery before mapping resumes.

### Recovery policy

Before changing verified `(0,0)` to `(2,0)`, the app durably stores an atomic
record under an exclusive lease. Recovery requires the same boot, continuously
attached HID/USB registry identities, USB location and descriptor, and proof
that the previous owner is dead. Original-pair readback must pass before the
same record nonce is cleared. Initial mode 2 without a record does not authorize
an inferred mode 0.

Changed attachment, malformed/stale records, live or reused PIDs and unknown
owners block mapping without guessed writes. An inactive blocked startup can
Quit while preserving its record; this owner's pending restoration still
blocks Quit. Same-port reconnect cannot bypass identity. Saved-mapping schema,
public API, layout and dependencies are retained.

### 복구 정책

확인한 `(0,0)`을 `(2,0)`으로 바꾸기 전에 exclusive lease 아래 atomic
record를 durable하게 저장합니다. 같은 부팅·계속 연결된 HID/USB registry
식별자·USB location·descriptor가 일치하고 이전 소유자가 종료됐음이
확인될 때만 복구합니다. 원래 값의 readback을 확인한 뒤 같은 nonce의 기록만
삭제합니다. 기록 없이 초기 모드가 2인 경우 0이었다고 추측하지 않습니다.

연결 변경, 잘못되거나 오래된 기록, 살아 있거나 재사용된 PID와 소유자 확인
실패는 추측한 값을 쓰지 않고 매핑을 차단합니다. 이전 기록 때문에 시작이
차단됐지만 활성 입력이 없는 앱은 기록을 보존하고 Quit할 수 있습니다. 현재
소유자의 미복구 상태는 계속 Quit을 차단합니다. 같은 포트 재연결로 식별을
우회할 수 없습니다. Saved-mapping schema, public API, layout과 dependencies는
유지합니다.
